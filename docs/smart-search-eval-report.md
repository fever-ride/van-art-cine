# Smart Search Eval Report

## Scope

This report captures the first backend evaluation pass for smart search v4.1:

- GPT query routing (`mode`)
- query intent classification (`intent_type`)
- response presentation (`result_type`)
- hybrid retrieval shape (`vector` / `lexical` / `both`)
- LLM verification/reranking
- fallback behavior

Frontend rendering is out of scope for this report.

## Notable Examples

### Duplicate Film Rows Fixed

Earlier agentic responses returned multiple rows for the same film when a film had multiple screenings. Example: `The Green Ray` appeared repeatedly for `dreamy melancholic romance`.

Current behavior:

```text
The Green Ray | result_type=film_results | showtimes=3
```

The response now has one film-level item with nested `showtimes[]`.

### Router vs Extractor Refinement

`light comedy tonight under 2 hours` contains hard constraints and recommendation intent. The router may classify it as constraint-heavy, but the extraction step can refine it:

```text
router intent_type: constraint_heavy_query
final intent_type: discovery_query
final result_type: film_results or empty_with_fallback
```

This is expected: router handles coarse retrieval mode, while extraction handles nuanced presentation intent.

### No-Result Honesty

For `tonight under 90 minutes`, the system returned an empty fallback rather than fabricating weak matches.

```text
message: No screenings found for those constraints.
```

This is preferred over returning irrelevant screenings.

## Planned Eval Harness

The next version of this report should be generated by a lightweight repo-local eval harness:

```text
eval/
  smart-search/
    labeled_queries.json
    run-live-eval.js
    metrics.js
    results/
      <timestamp>-live.json
      <timestamp>-report.md
```

Expected flow:

1. `labeled_queries.json` stores expected `mode`, `intent_type`, `result_type`, graded relevance labels, and `must_not_return` titles.
2. `run-live-eval.js` runs each query against the backend service/API and captures raw responses.
3. `metrics.js` computes routing/type accuracy, `Top1 hit`, `Recall@5`, bad result rate, and later `MRR` / `nDCG@5`.
4. Each run writes both machine-readable JSON and a human-readable Markdown report under `eval/smart-search/results/`.

## Known Gaps

- No labeled relevance dataset yet.
- No automated eval script yet.
- `this week`, `after 7`, and richer date/time expressions need better parsing.
- `light comedy tonight under 2 hours` produced no verified matches in the local snapshot; this may be correct for current data, but should be included in future labeled eval.
- Lexical recall currently indexes film-local fields (`title`, `normalized_title`, `genre`, `description`) but not joined person names.
- Frontend does not yet render each `result_type` differently.
